# 에이전트 두뇌 세팅 — 프롬프트 · 스킬 · MCP · 사용룰 (언어 중립)

TUI 껍데기가 절반이면, 나머지 절반은 에이전트를 "무엇을 어떻게 하게 할지" 정하는 설정이다. 이 규약은 Node/Rust/Python 어느 쪽이든 동일하다. Claude Code·stocker의 구성을 일반화한 것.

---

## 1. 시스템 프롬프트

역할·능력·경계·출력형식 4블록으로 짠다. 정적 텍스트에 **런타임 컨텍스트를 주입**한다 (모델명, 작업 디렉터리, 날짜, 사용 가능한 도구 목록).

```
# 역할 (Role)
너는 {제품명}, {도메인}용 터미널 에이전트다.

# 능력 (Capabilities)
- 사용 가능한 도구: {tool list}
- 접근 범위: {파일/네트워크/DB 경계}

# 경계 (Boundaries)
- 파괴적/외부로 나가는 작업은 실행 전 확인한다.
- {도메인별 금지사항}

# 출력 형식 (Output)
- 터미널 마크다운. 코드는 파일:라인으로 참조.
- 장황한 서론 금지, 결과 우선.

# 런타임 컨텍스트 (주입)
- Model: {model}   cwd: {cwd}   Date: {date}
```

원칙:
- **경계를 능력보다 먼저 못박는다.** "할 수 있는 것"보다 "하면 안 되는 것"이 사고를 막는다.
- **정적/동적 분리.** 프롬프트 본문은 상수, 컨텍스트만 매 세션 주입 → 프롬프트 캐싱 이득.
- **출력 형식을 명시.** 안 그러면 에이전트가 매번 다른 톤/길이로 답한다.

## 2. 스킬 (Skill)

에이전트가 상황에 맞춰 로드하는 도메인 지식/워크플로 묶음. 파일 하나(`SKILL.md`) + 프론트매터.

```markdown
---
name: <kebab-case>
description: <무엇을 하는지 + 트리거 문구들>  # ← 활성화를 좌우하는 핵심
---

# 스킬 본문
언제 활성화하는지, 절차, 주의점.
```

원칙:
- **description이 전부다.** 에이전트는 description을 보고 이 스킬을 꺼낼지 판단한다. "무엇을 + 언제(트리거 문구)"를 구체적으로.
- **지연 로딩.** 스킬 본문은 필요할 때만 컨텍스트에 넣는다. 이름/description만 상시 목록에 두고 호출 시 본문 로드.
- **멀티파일은 `references/`.** 본문이 길면 `SKILL.md`는 오케스트레이터로 얇게, 상세는 `references/*.md`로 분리하고 절대경로로 참조.
- **한 스킬 = 한 책임.** 여러 도메인을 한 스킬에 몰지 않는다.

## 3. MCP (Model Context Protocol)

외부 도구/데이터를 에이전트에 붙이는 표준. 서버를 config로 선언하고, 툴 스키마는 필요 시 로드한다.

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/allowed/path"]
    },
    "my-api": {
      "type": "http",
      "url": "https://mcp.example.com",
      "headers": { "Authorization": "Bearer ${API_TOKEN}" }
    }
  }
}
```

원칙:
- **stdio vs HTTP.** 로컬 프로세스는 stdio(`command`+`args`), 원격 서비스는 HTTP(`url`). 로컬 우선.
- **스키마 지연 로딩.** 서버가 수십 개 툴을 노출해도 전부 컨텍스트에 넣지 않는다 — 검색/필요 시점에 스키마를 가져온다.
- **접근 범위를 서버 인자로 제한.** 파일시스템 서버엔 허용 경로만, DB 서버엔 읽기 전용 크레덴셜.
- **시크릿은 env로.** config에 토큰 하드코딩 금지, `${ENV_VAR}` 치환.

## 4. 사용 룰 (Usage Rules)

에이전트의 행동 경계와 승인 정책. 프롬프트의 "경계" 블록을 운영 규칙으로 구체화한 것.

핵심 룰 세트:

| 범주 | 룰 |
|------|-----|
| **파괴적 작업** | 삭제/덮어쓰기/종료는 실행 전 대상 확인 + 사용자 승인. 프로덕션은 최대 주의. |
| **외부 전송** | 외부 서비스로 데이터 전송은 게시 행위 — 확인 후 진행. |
| **크레덴셜** | 읽기 전용/최소 권한 우선. 시크릿 하드코딩 금지, env/시크릿 매니저. |
| **도구 사용** | 전용 도구가 있으면 셸보다 그걸 쓴다. 독립 작업은 병렬 호출. |
| **승인 정책** | 자동 승인은 신뢰된 정형 작업만. 탐색적 작업은 수동 승인. |
| **입력 검증** | 신뢰 경계(사용자 입력, API 응답, 파일)에서 항상 검증. |

원칙:
- **되돌리기 어려운 작업은 기본이 "확인".** 한 번 승인이 다음 작업까지 확장되지 않는다.
- **불확실하면 프로덕션으로 가정.** 리소스가 prod인지 모르면 최대 주의.
- **룰을 프롬프트 + 런타임 게이트 둘 다에.** 프롬프트로만 막으면 새어나간다 — 파괴적 툴 호출 앞에 코드 레벨 확인 게이트도 둔다.

---

## 조립 순서

1. 시스템 프롬프트 4블록 작성 (경계 먼저)
2. 도메인별 스킬을 `SKILL.md` + `references/`로 분리, description에 트리거 명시
3. 필요한 MCP 서버를 config로 선언, 접근 범위 제한, 시크릿 env화
4. 사용 룰을 프롬프트 경계 + 런타임 게이트 양쪽에 심기
5. 초기화면 상태 줄에 현재 모델/모드/cwd 노출 (사용자가 경계를 볼 수 있게)
